# Quickmd 编辑器 · 实现说明

> 本文描述**当前实现**，不是历史沿革。
> 想了解整体结构看 `MAP.md`，想快速上手看根目录 `README.md`。

---

## 0. 一句话概览

一个**分块所见即所得的 Markdown 编辑器**：文档被切成「块」（标题 / 段落 / 列表 / 引用 / 代码 / 分隔线），每块独立渲染、独立编辑；保存时把 DOM 反序列化回标准 Markdown 写盘。普通打字不动 DOM，光标不跳。

---

## 1. 核心编辑功能

### 1.1 支持的格式

| 格式 | Markdown 写法 | 渲染效果 |
|---|---|---|
| 一至六级标题 | `# ` … `###### ` | 逐级递减的标题 |
| 加粗 | `**文字**` | **文字** |
| 斜体 | `*文字*` 或 `_文字_` | *文字* |
| 删除线 | `~~文字~~` | ~~文字~~ |
| 行内代码 | `` `代码` `` | 等宽底色 |
| 链接 | `[文字](https://…)` | 可点链接，新标签打开 |
| 裸 URL | 直接粘贴 `https://…` | 自动变链接 |
| 无序列表 | `- ` / `* ` / `+ ` | 圆点列表，支持缩进嵌套 |
| 有序列表 | `1. ` | 编号列表，支持缩进嵌套 |
| 任务列表 | `- [ ] ` / `- [x] ` | 可点击勾选框 |
| 引用 | `> ` | 左侧竖线引用块 |
| 代码块 | ` ``` ` 围栏 | 等宽块，首行可写语言名 |
| 分隔线 | `---` / `***` / `___` | 水平分隔线 |
| 表格 | `\| 甲 \| 乙 \|` + 分隔行 | 真表格，支持 `:---:` 对齐 |
| 图片 | `![说明](路径)` | 显示图片；粘贴图片会自动落盘 |

### 1.1.1 表格

- **粘贴即用**：从别处复制一段 Markdown 表格粘进来，直接渲染成表格。
- **单元格内**：`Tab` 跳到右一格（最后一格跳到下一行首格），`⇧Tab` 回退，`回车` 在当前行下方插一行。
  - 这三个键必须拦在 `keydown` 的**捕获阶段**：contenteditable 里事件的 `target` 是编辑宿主而不是 `<td>`，用 `e.target.closest('td')` 在冒泡阶段拿不到单元格。
- **写回**：`tableMD()` 会补齐表头分隔行、把单元格内换行降级为空格、`|` 转义成 `\|`——Markdown 表格不支持单元格内多行，不降级就会把表格写坏。
- **对齐符**：`| --- | :---: | ---: |` 里的对齐标记会保留，不做归一化。

### 1.1.2 图片

- **md 里存相对路径，显示时换绝对路径**：`<img data-rel="assets/cat.png" src="file:///…/assets/cat.png">`。
  - 写回 md 一律用 `data-rel`。存绝对路径的话，文件夹一搬走图片就全断。
  - 网络图片（`http(s)://`）不改写。
- **粘贴落盘**：粘贴板里的图片会 `postMessage({type:'saveImage'})` 给 Swift，存进文档同级的 `assets/`，再以相对路径插进正文。

### 1.2 快捷键

**界面没有工具栏**，所有格式靠「前缀语法 + 快捷键」进入。

| 快捷键 | 功能 |
|---|---|
| `⌘B` / `⌘I` / `⇧⌘X` | 加粗 / 斜体 / 删除线 |
| `⌘1` `⌘2` `⌘3` | 当前块转一/二/三级标题 |
| `⌘7` `⌘8` `⌘9` | 当前块转无序/有序/引用 |
| `Enter` | 拆出新块；列表项末按则续项或退出列表 |
| `Backspace` | 行首按下则剥掉块标记，降级为普通段落 |
| `Tab` / `⇧Tab` | 列表项缩进 / 减缩进 |
| `Esc` | 关闭面板（内容已自动保存） |

行内代码没有快捷键，链接没有插入入口（见 1.4）。

### 1.3 编辑行为规则

- **敲前缀即变形**：在普通段落行首敲 `# `、`- `、`> ` 等，输入停顿即自动转成对应块。
- **光标保持**：变形后用「文本偏移」恢复光标位置，不用浏览器 Selection 的 sticky 逻辑，光标不会跳到块尾。
- **点击空白聚焦最后一块**，与系统快速备忘录一致。
- **有序列表续号按 Typora 的规矩**：写 `1. ` 回车变 `2.`，再回车变 `3.`；写 `3. ` 就从 3 开始（3、4、5…），存盘后重新打开序号不丢。空列表项上再回车会**退出列表**变成普通段落。

### 1.4 安全规范

- 所有用户文本进 DOM 前 **HTML 转义**（`& < > "`），脚本标签无法注入。
- 链接协议**白名单**：仅放行 `https?://` `mailto:` `tel:` `#` `/` `./` `../` 及相对路径；`javascript:` `data:` `vbscript:` 等一律降级为 `#`。
- 属性边界转义：URL 进 `href` 前二次转义，防止 `"` 突破属性边界。
- **链接只能手写 Markdown**：`[文字](url)` 会渲染成可点链接，但没有「选中文本弹框插入」的入口，因此不存在 URL 绕过 `safeURL` 的路径。
- 以上规则有单测覆盖（`Tests/editor-core.test.js` 的 XSS 组）。

## 2. 文档的打开与加载

| 方式 | 操作 |
|---|---|
| 默认便签 | 首次启动自动加载 `~/Documents/Quickmd/scratch.md`，不存在则创建空白文件 |
| 菜单打开 | 状态栏菜单 →「打开 Markdown 文件…」或 `⌘O` |

不支持拖拽打开文件。

### 2.1 加载链路

```
启动
 └─ AppDelegate 建 WKWebView，loadFileURL 加载 editor.html（本地资源包）
     └─ JS init() → post({type:'ready'})
         └─ Swift 收到 ready → 读 storeURL 内容
             └─ evaluateJavaScript: window.QN.load(JSON字符串, 文件名)
                 └─ JS: parse(md) → blocks → 逐块 createBlockEl → DOM
```

关键点：

- WebView 加载的是 **app 资源包内的本地 HTML**（`Bundle.module` → `editor.html`），不走网络，无远程依赖。
- Swift→JS 走 `evaluateJavaScript`，内容以 **JSON 字符串**传递（`JSONSerialization` 生成），避免引号注入 JS 上下文。
- JS→Swift 走 `WKScriptMessageHandler`（通道名 `quickmd`），只有两类消息：`ready`（编辑器就绪，可以推内容了）、`save`（携带序列化好的 md）。

### 2.2 保存链路

```
用户输入 → scheduleSave() → 200ms 防抖 → flush()
   └─ getMarkdown(): 遍历 .qn-block，blockMD() 逐块序列化，块间 '\n\n' 连接
       └─ post({type:'save', md})
           └─ Swift saveContent(md) → 写盘（storeURL 或当前打开的文件）
```

- **防抖 200ms**：停笔约 0.2 秒后落盘，打字过程中不重复写文件。
- **Esc / 关面板前强制 flush**：立即保存最后输入的内容，避免丢字。
- **块间空行**：块与块之间用空行连接（CommonMark 规范），存出的 `.md` 文件在 Typora/VS Code 等标准渲染器里段落不会并成一块；本编辑器重新打开时块结构也保持稳定（有单测覆盖）。
- **没有手动保存入口**：停笔后自动保存，Esc 或收起面板时立即保存。

## 3. 界面与交互

### 3.1 面板两态

```
① 鼠标碰到屏幕顶部刘海区域
      ↓  面板滑出（330×285pt，与系统快速备忘录同尺寸），此时是「预览态」——
      │  不抢键盘焦点，别的窗口照常打字
② 点击面板
      ↓  进入「激活态」：面板获得键盘焦点，可以打字；
      │  面板被「钉住」，鼠标移开也不收起
③ 编辑：所见即所得，⌘B/⌘1/敲前缀 随便用
      ↓  停笔 0.2 秒自动存盘；Esc 前再强制存一次
④ Esc（或点击面板外）
      ↓  面板收起，内容已落盘
```

- **hover 不 activate**：预览态只 `orderFrontRegardless()`，绝不抢焦点——这是「不打扰」的关键。
- **停留区（stay region）**：鼠标从刘海移进面板的路径上有一片判定区，防止「一碰刘海→展面板→鼠标往下移→判定离开→面板抖一下收起」。
- **钉住（pin）**：点击面板后 `isPinned = true`，此时鼠标满屏跑面板都不收；只有 Esc 或失活才收。
- **30Hz 轮询 `NSEvent.mouseLocation`**：不用全局鼠标监听，因此**不需要辅助功能权限**，系统设置里零授权项。
- **刘海几何自适应**：`safeAreaInsets.top > 0` + `auxiliaryTopLeft/RightArea` 实时计算刘海宽度。

### 3.2 视觉

- 参照 **macOS 备忘录**：暖白纸面、大标题层级、宽松行距、发丝线、柔和投影。
- **固定浅色**，不跟随系统深浅色。WebView 外观被强制为 `NSAppearance(named: .aqua)`，任何系统主题下都是同一张暖纸面。
- **没有工具栏、没有底栏、没有状态栏**：正文区铺满整个面板，保存自动进行。

## 4. 内存占用

> **先看单位，别读错**：下面数字是**内存占用**，不是文件大小。
> 一个测试文件本身只有 **72 KB**，只是内容碎、被切成了 **1286 个块**。

| 场景 | 主进程 | WebContent 子进程 | 总计（内存占用） |
|---|---|---|---|
| 空文档（基线） | 20 MB | ≈17 MB | **≈37 MB** |
| 日常小文档（几百字） | 20 MB | ≈17 MB | **≈37 MB** |
| 大文档 72 KB / 1286 块 | 20 MB | ≈22 MB | **≈42 MB** |

结论：

- **日常使用约 37 MB**——作为参照，一个 Chrome 标签页通常 100–300 MB。
- **文档规模对内存几乎不敏感**：1286 块的大文档也只多 5 MB。因为分块渲染后每块只是一个小的 contenteditable div，且只有变形时才重建 DOM。
- **主进程 20 MB 是固定底座**（Swift 运行时 + NSPanel + 刘海轮询定时器），与文档无关。

## 5. 代码结构

### 5.1 编辑器三层

```
Quickmd/Sources/Quickmd/Resources/
├── editor.html        # 界面骨架（无工具栏、无底栏）
├── editor.css         # 样式：固定浅色的备忘录风暖纸面
├── editor-core.js     # 纯函数内核：esc/inline/parse/renderBlock/…
│                       #   —— 无 DOM 依赖，Node 里可直接跑单测
└── editor.js          # 浏览器层：DOM 序列化 / 块操作 / 事件 / 对外接口
```

**分层的意义**：`editor-core.js` 里全是纯函数（输入字符串、输出字符串），所以能脱离浏览器在 Node 里跑 103 项单测；`editor.js` 里的 DOM 行为靠 `--domtest` 诊断开关在真实 WebView 里自检。

### 5.2 数据流

```
   Markdown 文本                用户看到的/编辑的
        │                            ▲
        ▼                            │
  ┌───────────┐   renderBlock   ┌──────────┐
  │  parse()  │ ──────────────▶ │   DOM    │
  │  md→blocks│                 │ 分块渲染  │
  └───────────┘                 └──────────┘
        ▲                            │
        │   blockMD/serializeNode    │ 打字（不动 DOM）
        └────────────────────────────┘
                 保存时（200ms 防抖）
```

**核心设计决策**：只有「需要变形」的操作（敲前缀、勾任务、⌘B 包裹、⌘1 切标题）才走「序列化当前块 → 改 md → 重渲染该块 → 按文本偏移恢复光标」；普通输入交给浏览器原生 contenteditable 处理。这就是光标不跳、性能够好的根本原因。

### 5.3 对外接口（JS → Swift）

`window.QN` 暴露四个方法：

| 方法 | 用途 |
|---|---|
| `load(md, file)` | 载入文档，解析成块并渲染 |
| `getMarkdown()` | 把当前 DOM 序列化回 Markdown |
| `flush()` | 立即触发一次保存（不等防抖） |
| `core` | 暴露 `editor-core.js` 的纯函数（供自检脚本使用） |

## 7. 已知边界

1. **不支持脚注、公式、Mermaid**——刻意砍掉：快速便签场景用不到，且每加一种块类型，序列化往返的测试面就翻一倍。需要时按现有块模式扩展即可（`parse → renderBlock → blockMD` 三处对称加）。
2. **多文档不并存**：同时只有一个活动文档，打开新文件即切换。符合「快速备忘录」心智。
3. **代码块内不语法高亮**：只做等宽 + 底色，语言标签仅作标记保留。
4. **没有手动保存**：依赖自动保存（200ms 防抖）与关闭前强制落盘。
