# Quickmd 浅色界面重构 Demo

- **任务：** 给刘海便签面板做一版可预览的界面重构方案，只保留浅色模式。
- **北极星：** 一眼看到文件和正文，打开后立刻能写；保存和勾选状态清楚但不抢内容。
- **产品与主动作：** 这是 330×285pt 的 Markdown 速记面板。主动作是直接编辑内容、勾选待办。
- **方向：** 延续暖纸面和清楚的文字层级，把文件名移到顶部、把保存状态和字数收进底栏。强调色用陶土红做光标和待办勾选，状态颜色单独保留。
- **浅色配色：** 纸面 #F8F6F1；正文 #292722；次要文字 #716D64；强调色 #A14D32；边界线 #E7E1D7。
- **关键状态：** 默认内容、空白便签、未保存、待办已完成/未完成；没有深色模式。
- **动效：** 首次打开时页眉、正文、底栏依次短暂出现；按下打开按钮有轻微收缩；勾选框颜色和状态文字平滑切换。减少动态效果时直接显示最终状态。
- **交互：** 可直接编辑、点击待办勾选、导入 .md 文件；Demo 自动保存到浏览器本地存储，导入后编辑不会写回原文件。
- **边界：** 这是独立 Demo，不改生产 App 的 HTML/CSS/Swift。选定后再把这套样式接回 App。
- **验收视口：** 330×285pt；检查浅色、空白、未保存和待办状态；滚动只发生在编辑区。

## 预览

打开 index.html。也可加地址状态参数：

- ?state=ready
- ?state=empty
- ?state=unsaved

## 验收记录

- 在 330×285pt 下查看默认、空白和未保存状态；检查没有横向溢出、控制台报错、图片加载问题或对比度提示。
- 实际点击待办框，看到勾选状态变化，保存状态从“未保存”回到“已保存”。
- 入场和勾选的关键帧保存在 evidence/ 和 evidence-interaction/；环境未安装 ffmpeg，因此没有生成录屏文件。

## 取舍

- 保留现有的直接编辑、待办勾选和自动保存习惯。
- 文件名从底栏移到页眉，底栏只呈现保存状态和字数，减少状态信息挤在一行。
- 不加品牌大标题、工具栏或额外说明，给正文留空间。
- 只在这个 Demo 中去掉深色模式；生产 App 仍保持原样，避免把设计稿误当成已上线的产品改动。
