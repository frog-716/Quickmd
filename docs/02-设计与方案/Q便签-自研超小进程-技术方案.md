## 二、便签粒度（通俗版解释）

同一个问题：**你写的所有便签，放在哪里、怎么找、怎么搬进备忘录。**

- **A. 单暂存文件**：就像桌上永远摊着一张便利贴，什么都往上写，新的接在旧的下面。好处是零管理；坏处是攒一个月后找上周的内容要滚很久。搬进备忘录 = 把整张纸一次性追加过去。
- **B. 按天自动分文件**：每天凌晨自动换一张新纸，纸上自带日期。找哪天翻哪天，天然时间线。搬进备忘录 = 选今天（或某天）那段追加。
- **C. 多便签列表**：App 左边一列标题，像个小备忘录，点哪篇编辑哪篇。管理最强，但这个进程就从「一张纸」变成「一个库」，复杂度和体积都上一个量级——和你「超小进程」的初衷有冲突。

我的建议：**B 起步**。它和 A 一样零文件名管理，又自带时间线，回写时「今天写的东西今天搬」语义最干净。A 适合用量极小的人；C 等哪天 B 不够用了再升级，不现在付复杂度税。

## 三、编辑器内核（通俗版解释 + demo 结论）

三种内核的区别只有一个：**你打字的时候，屏幕上出现的是「源码」还是「成品」。**

- **① 混合实时渲染**：屏幕上看起来是成品，但你光标停在哪一行，哪一行就临时露出 `**`、`#` 这些符号。Bear、Typora 都是这个路线。最轻，但自己实现一个稳的渲染引擎最难（要处理光标、选区、输入法）。
- **② 真所见即所得**：满屏一个符号都没有，跟飞书文档一模一样；加粗靠 ⌘B 或选中出工具条，markdown 语法粘进去也能自动变成格式。实现最容易（一个网页视图 + 一份 CSS 皮肤），代价是包体约 40MB、内存约 60MB——但你的 M5/16GB 完全无感。
- **③ 双栏**：左边源码右边预览，最轻最容易，但每次写作都要左右眼分工，飞书感最弱。

demo（见对话内交互演示）验证了：② 用一两百行代码 + CSS 就能做出飞书皮肤。**推荐：demo 阶段用 ② 起步**，手感确认后再评估要不要为省内存换 ①。

## 四、架构设计

```
QNote.app（一个文件，~40MB，菜单栏可选图标，无 Dock 图标）
├── main.swift          — 入口：NSApplication 设为 accessory（LSUIElement）
├── HotZoneMonitor      — 屏幕级鼠标位置监听（NSEvent 全局监听，零权限）
│   └── 鼠标进入主屏右下角 240×140 热区 → 滑出面板；离开热区+面板 → 延迟收起
├── PanelWindow         — NSPanel（浮动级、圆角、毛玻璃、可成为主窗口）
│   └── WKWebView       — 本地 editor.html（marked.js 解析 + 飞书皮肤 CSS + turndown 存回 .md）
├── Store               — ~/Documents/QNote/ 下读写 .md（防抖 500ms 自动存盘）
└── RecallBridge        — 「回写备忘录」按钮 → 调用 macOS 自带 shortcuts 命令行：
                          shortcuts run "追加到备忘录" -i <内容>
                          （用户一次性手工建好这个快捷指令，之后 App 内一键完成回写）
```

**四条设计原则**：
1. **零权限**：不用 CGEventTap（那才需要辅助功能授权）、不读写备忘录数据库、不常驻网络。整个 App 只碰 `~/Documents/QNote/` 和调用一次快捷指令。
2. **零干扰**：不进 Dock、不进 Cmd-Tab 列表可视区（accessory 模式）、默认开机不启动（你要用才有）。
3. **热区是唯一入口**：鼠标推到屏幕右下角 → 面板从右下角滑出（动画 150ms）；鼠标离开面板和热区 1.5 秒后自动收起；热区尺寸写在配置里可调。
4. **数据单向上浮**：.md 是草稿，备忘录是成品。回写=追加（沿用已验证的最稳路径），不原地替换。

## 五、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言/构建 | Swift 6 + SwiftPM（CLT 可编译） | 本机现成工具链，零额外安装 |
| 外壳 | AppKit accessory app + NSPanel | 系统级面板标准做法，NotchNotes/Open Sidenotes 同款路线 |
| 编辑器 | WKWebView + 本地 HTML（marked + turndown + 飞书皮肤 CSS） | 内核②；Markdown 解析/HTML 回写用 JS 库，Swift 侧零解析负担 |
| 存储 | 纯 .md 文件 + 按天或单文件（待第二节决策） | Finder 可见、Time Machine 全覆盖、Typora 随时能打开 |
| 回写备忘录 | `shortcuts run` CLI 调用户预建的快捷指令 | 绕开 .shortcut 文件签名不可编程的问题；只追加，最稳 |

## 六、安全与权限

- **不需要任何系统授权**：鼠标热区用 NSEvent 全局监听（接收而非拦截按键/点击，不碰辅助功能权限）；回写备忘录走 Shortcuts（用户授权给 Shortcuts，不给我们）。
- **Gatekeeper**：本地 swift build 产物无隔离标记，直接可运行；若拷贝到别的机器需右键打开。
- **不碰红线**：不关 SIP、不注入备忘录、不写 NoteStore.sqlite、不装任何第三方工具。

## 八、风险与未决点

1. **热区误触**：右下角也是「显示桌面」等系统手势常见区。对策：热区只占右下 240×140 且需鼠标「进入并停留 ≤300ms」才触发；手势冲突实测后再调。
2. **WebView 回写 .md 的往返保真**：marked 解析 + turndown 序列化对怪异 md 结构可能改写（如多余空格、列表缩进）。对策：P1 用你手头的 3-5 条真实笔记测往返，不可忍受再换方案。
3. **快捷指令回写依赖用户手工建一次**：这是唯一无法全自动的环节（Apple 不允许程序化创建签名 .shortcut）。P2 给你图文步骤，5 分钟一次性投入。
